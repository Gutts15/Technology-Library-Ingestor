# Technology Library — Public Roadmap

CHARTER_VERSION: 1.1
PROJECT_STATUS: IN_PROGRESS

The public repository holds reusable automation code only. The private Drive
remains the authority for source media, processing state and canonical records.
The North Star remains automatic inbox-to-canonical knowledge and routed retrieval,
with recovery, privacy, no routine human approvals, no user PC and R$0 additional
mandatory recurring cost. Charter 1.1 records the owner-approved acceptance revision;
the 500-item scale test is outside V1. No acceptance result is implied by that revision.

## Five approved milestones

1. **Initial integration — accepted for the existing subsystem proofs.** Existing
   integration/CI is preserved. Scheduled fixture proofs do not establish production.
2. **Production transactional E3 — partial.** Reuse the existing publication,
   shared coordinator, snapshots, journal, commit and recovery mechanisms. Complete
   only after one authorized remote Drive + shared GitHub chain proves exclusive
   ownership, concurrent-publisher rejection, CREATE/UPDATE, indexes, receipts,
   interruption/lost confirmation/restart reconciliation and stale-writer protection.
   Local Git CAS and disposable Drive proofs are insufficient for this milestone.
3. **Integrated E1 + E2 + E3 — partial.** Qualify real bounded extraction and
   provenance, free-tier Gemini decisions, lot hashes, identity-preserving publication,
   all five dispositions, deduplication and continuation after model failure. Synthetic
   evidence scenarios are contract tests. Actual encoded-file extraction and a local
   CREATE/UPDATE chain now have decoder/integration tests; live model, speech/link
   completeness and the shared cloud chain remain unproved. See
   `V1_MEDIA_OPERATION_QUALIFICATION.md` for exact proof boundaries.
4. **Production activation — pending.** After safety/integration gates pass, connect
   the single operational chain to Actions, recover before new work, remove the
   fixture-only restriction on the authorized production path, preserve the inbox
   backlog and originals, verify secrets by existence/function, and prove a real
   CREATE/UPDATE plus routed readback. Update existing supervision. A created or
   dispatched workflow is not proof of activation.
5. **Final acceptance — NOT_RUN.** Seven consecutive real scheduled days must
   cover empty day, CREATE and routed retrieval, identity/content-preserving UPDATE,
   duplicate UNCHANGED without reanalysis, irrelevant REJECT, weak-evidence HOLD,
   failure and next-cycle recovery, private public logs/artifacts, and Drive credentials
   working for more than eight days without manual renewal. Preserve private proof;
   publish only sanitized aggregate evidence. Only then declare V1 COMPLETE.

## Dependencies and exit

Milestone 2's shared remote authorization blocks its operational proof and safe
production activation. Independent extraction, contract, integration and documentation
work may proceed without bypassing that restriction. Production must preserve a
single writer; no alternate token, transport or workflow may bypass an administrative
block. Administrative setup is exceptional and must not become a recurring user step.

V1 completion requires every milestone and the Charter black-box acceptance pass.
The project remains IN_PROGRESS and real acceptance remains NOT_RUN. Beyond V1:
500-item scale testing and the other exclusions in specification V1.2.0; no additional
V1 milestone or silent scope expansion is introduced.
